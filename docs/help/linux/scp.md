# scp

SSH を使ってリモートホストとの間でファイル・ディレクトリをコピーする。
rsync と違って差分転送はせず、指定した範囲を毎回まるごと転送する。
その代わり rsync が入っていない環境でも SSH が使えれば動くため、単発のコピーに向いている。

```bash
scp [オプション] [転送元] [転送先]

# 例: リモートからローカルにファイルを転送する
scp username@hostname:/var/www/html/index.html ./

# 例: ローカルからリモートにディレクトリを転送する
scp -r ./dist username@hostname:/var/www/html/

# 例: リモート同士で転送する（データは一度このマシンを経由する）
scp -3 user1@host1:/path/to/src user2@host2:/path/to/dest
```

## オプション

|       オプション        | 意味                                                                      |
| :----------------------: | :------------------------------------------------------------------------ |
|     `-r` / `--recurse`   | ディレクトリを再帰的にコピーする                                          |
|          `-p`            | ファイルの更新日時・アクセス日時・パーミッションを保持する               |
|          `-C`            | 転送データを圧縮する                                                      |
|          `-v`            | 詳細なデバッグ情報を出力する                                              |
|          `-q`            | 進捗表示やメッセージを抑制する                                           |
|        `-P [port]`       | 接続先の SSH ポートを指定する（`ssh` の `-p` とは大文字小文字が逆）        |
|       `-i [path]`        | 認証に使う秘密鍵ファイルを指定する                                        |
|      `-l [limit]`        | 帯域幅を Kbit/s 単位で制限する                                            |
| `-3` / `--no-posixrlimit` | リモート間転送時にデータをこのマシン経由にする（デフォルトは直接転送）    |

## rsync との違いに注意

- 差分を見ずに毎回全体を転送するため、大きなファイルや何度も同期する用途では rsync の方が速い
- 転送が中断すると再開できず、同じコピーを最初からやり直すことになる
- 転送先にすでに同名のディレクトリがあっても `-r` の挙動は `cp` に近く、末尾の `/` の有無による差は rsync ほど大きくない

## ユースケース

```bash
# 秘密鍵とポートを指定してリモートから設定ファイルを取得する
scp -i ~/.ssh/id_ed25519 -P 2222 username@hostname:/etc/myapp/config.yml ./config.yml

# パーミッションとタイムスタンプを保ったままディレクトリ全体をアップロードする
scp -rp ./build username@hostname:/var/www/html/

# 帯域を絞って大きなファイルを転送する（本番帯域を圧迫しないように）
scp -l 1000 ./backup.tar.gz username@hostname:/backup/
```
